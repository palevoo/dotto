# Architecture

Native SwiftUI on iPhone and Mac. The copy that counts lives on your devices. Every
other reader is a grant, and weeju is one of those readers.

§0 is what is built, as of November 2026. §1 to §8 are a sketch of where it could grow,
written before any of it was used. Treat them as ideas, not decisions.

## 0. Iteration one (what is built)

A folder you own, an app that writes into it, nothing else.

    <notebook>/
      notebook.json                  id, created, owner
      events/<author>.<device>.jsonl one writer per file, append-only, one event per line
      media/<hash>.<ext>             photos and audio by content hash
      days/YYYY-MM-DD.md             derived, regenerated by the projector

The folder lives in the person's iCloud Drive. Each device appends only to its own file,
so there are no conflicts by construction and no sync code. The Mac sees it in Finder.
weeju, or any agent, takes part by appending to its own event file with its own author;
the phone folds it in and shows the note under the line. The door is the folder.

In: the Core package (events, fold, file store, day projector, the door, tests), the
iPhone app (page, pinned date and calendar, live line, photo, voice), and a first Mac app
that is only the grant holder: sandboxed, sees the one folder you pick, shows the grants
list, and serves the door (MCP over localhost, one key per grant). SQLite as a derived
index only when the in-memory fold gets slow.
Out, by decision: video, Mac app, extensions, labels, to-dos, grants, accounts, server,
custom encryption. All later readers of the same files.
Risk: iCloud Drive on iOS can be slow to pull files. If it bites, the same event lines
move to CloudKit records with the fold unchanged.

Everything below this line is a sketch.

## 1. The one data structure

Everything is an event in an append-only log. An event is small and immutable:

    id        ULID (time-ordered, globally unique, made on the device)
    notebook  whose log this is (one per person)
    author    the person, "weeju", or another grant holder
    device    device id
    at        wall clock when it happened
    kind      one of a short vocabulary
    payload   JSON, shape fixed per kind

Kinds, first vocabulary:

    entry.create   {entry, text, at, loc?}          a line, with the moment it started
    entry.edit     {entry, text}                     you changed the words
    entry.delete   {entry}                           tombstone
    media.attach   {entry, hash, mime, w, h, dur?}   photo, video or audio, by content hash
    media.caption  {entry, hash, text}
    place.resolve  {entry, name}                     a reader names the coordinates
    note.add       {entry, note, text}               a reader's line under yours
    note.remove    {note}
    label.attach   {entry, label}                    never typed by you
    label.detach   {entry, label}
    link.add       {later, earlier, closes}          a later line carries on from an earlier one;
                                                     closes: it finished what the earlier one opened
    link.remove    {later, earlier}                  the owner takes a link back
    visit          {what, since?, label?, count, …}  a reader's receipt for a read
    grant.create   {grant, to, slice, mode, scopes}  see §4
    grant.revoke   {grant}

Beside the events, not among them: `devices/<device>.json`, where a phone leaves the
address Apple gave it for pushes. Whoever holds the folder and the account's push key can
reach the phone; today that is the Mac, when a note lands through the door.

An entry is the fold of its events, ordered by id with device time as tiebreaker. A day
is a group of entries. Nothing is overwritten. Edits are events, so history exists
without a versions feature.

**The invariant.** Only the owner ever writes `entry.*`. Every other author, weeju
included, appends to its own layer: notes, labels, links, views. A layer is removable
wholesale by author. Different author, different ink. A to-do is not a kind: an
intention is a line, and the line that carries it out links back with `closes`.

Conflicts: two devices editing one line in the same minute is the only case, last write
wins. The live line alone can become a text CRDT later if it ever matters.

## 2. Where it lives

    device      the event log, materialised views, media, FTS         SQLite via GRDB
    sync        the same log, encrypted, between one person's devices  CloudKit private db
    folder      plain files folded from the log, readable without us  iCloud Drive
    relay       encrypted projections passed between people            Railway, later

**Device.** SQLite through GRDB in an App Group container, so the Share Extension,
widgets and App Intents append events directly. Tables: `events` (append-only, synced
flag), `entries` and `days` (materialised, rebuildable), `media` (hash, path, upload
state), FTS5 over text. Media as files under the hash, thumbnails made on device.

**Sync.** CloudKit private database, every field marked encrypted. With Advanced Data
Protection on, neither Apple nor we can read it; without, Apple holds the key and we
still cannot. Said to the person in one sentence. Offline is the default, not a mode.

**Folder.** `days/2026-11-02.md`, `media/<hash>.jpg`, `atoms/*.yaml`, `views/`. Written
by the Mac app into the person's iCloud Drive, readable in Finder without us. Regenerated
by a deterministic fold, so it is never the source of truth and never wrong for long.
Export from day one is this folder as a zip plus every event as JSON.

**Relay.** One Railway project: Postgres and a small Swift service that stores
encrypted blobs addressed by grant and passes them to recipients. It cannot read them.
It does not exist until grants between people exist.

## 3. The door

The notebook exposes one interface, and everything that is not the owner's own typing
goes through it:

    read       a granted slice, as events or as the folded files
    append     events to the caller's own layer, within the caller's scopes
    subscribe  to new events in the slice

weeju uses this door. So does a local MCP server on the Mac, so Claude Code or any MCP
client reads the terreno slice the way weeju does. So does a bot on a machine the person
chose. The door is the Core package's public API; the app is its first client, weeju the
second. Keeping weeju outside the door is a rule, not a feature.

## 4. Grants

A grant is a standing projection with a recipient. Nothing is shared any other way.

    to       a person, an agent, or anyone with the link
    slice    a filter over the log: labels, a time window, a derived view
    mode     live (new events flow) or snapshot (what it was on the day it was sent)
    scopes   read; write notes; write atoms; publish views; forward

The projector folds the slice into files, encrypts them to the recipient's key, and the
relay carries them. The recipient's app folds them in as a read-only layer in another
ink. "Space" is not a primitive: a shared place is a live grant to a few people.

Grants live entirely on the reading side. The page is blind to who reads it, and grants
are applied later and by slice, never per line. A grant is a promise forward, not control
backward: a snapshot already read cannot be unread, and the interface says so.

The grant list is the privacy screen. One row on day one: weeju, read all, write notes
and atoms, runs on this Mac. Each row shows where the reader runs, because that is where
plaintext goes.

## 5. weeju

A process holding a grant, running where the plaintext already is:

    on the Mac when it is on            the natural home, scheduled passes possible
    on the iPhone while charging        background task, short passes
    on a hosted machine, if granted     a row in the list like any other

Trigger: new events in its slice, debounced, or a schedule. It reads the folder, thinks
with a model called transiently, appends through the door, stops. The model provider sees
the slice during the call and keeps nothing. Small things (labels, spotting a to-do) can
use the on-device model; anything that thinks hard goes to a cloud model, and the person
is told that in one sentence. weeju can be turned off per slice and writing continues.

What weeju does is deliberately undecided until real entries exist (§7 step 3).

## 6. Privacy, said plainly

- Your words never leave your devices in the clear, except to a reader you granted, at
  the place the grant row names.
- Export at any time: the folder as a zip, every event as JSON, every media file.
- Delete is a tombstone everywhere, then a purge, and a revoke of every live grant.
- Location is coordinates captured with a one-time permission and named later by a
  reader. Never a prompt while writing.
- No analytics. Crash reports through Apple only.

## 7. Order of work

1. `Core` package: the vocabulary, the fold, the door as a Swift API, unit tests.
2. iPhone app: the page, pinned date, live line, local SQLite, photo, voice, hold video.
   Export to the folder from day one. Used on real visits with no sync and no weeju.
3. Read the real entries from a few visits. Only then ideate the first-generation loop
   end to end, as a spec against those entries.
4. CloudKit sync. Mac app from the same code, writing the folder into iCloud Drive.
   Share Extension. Local MCP server over the door.
5. weeju on the Mac, holding the first grant, doing the first thing the entries asked for.
6. Relay on Railway. Grants to people. Your partner on TestFlight.

## 8. What "high quality" means for the apps

- One Swift package, `Core`: event types, the fold, the projector, the door. Used by
  iPhone, Mac, and weeju. The vocabulary in §1 is code, not a document.
- The page is a UIKit text stack under SwiftUI: a growing text view per entry and one for
  the live line, in one lazy scroll of days, keyboard handled by the layout guide so the
  page scrolls under it. SwiftUI's TextEditor is not good enough here.
- Bundled fonts: Newsreader, IBM Plex Sans, IBM Plex Mono.
- Capture: camera through AVFoundation with the rounded-square frame and hold-to-record;
  audio with on-device speech recognition, so the text is the entry and the audio sits
  behind it; Share Extension; App Intents for Siri and the Action button; a lock screen
  widget with write, photo, speak.
- Mac: the same page, keyboard first, drag files onto the page, a menu bar quick entry
  with a global shortcut.
- One shape language: a continuous-curvature rounded square at a fixed radius ratio for
  everything made. Text has no shape.
