# Study: patterns for the milestone

6 November 2026. Research by the author, with three parallel passes over publishing,
running loops, and data and ways in. Proposals here are the author's, not decisions.
The milestone is in `milestone.md`.

## Patterns that fit

**Local-first with a dumb relay.** The notebook already is local-first: append-only files
per author per device, no merge. Ink & Switch's current direction (Keyhive, Beelay) is the
same shape with a relay that only holds ciphertext for reach when the device is off. A relay
adds reach, nothing else. We can add it last.

**Event log, projections.** Everything we show is folded from events. Records are one more
projection. The note tools that handle structure best without making the person file
(Logseq DB, Tana) do what we already do: a label is a schema, the fact lives on the line,
tables and views are derived. The recurring pitfall across Obsidian, Dataview, Tana and
Notion is facts the view engine cannot see and field names drifting across types. One open
fact on a line, folded into one SQLite file per notebook, avoids both.

**Pages are files.** No scripts from people. Each person on their own origin
(name.dotto.works), `Content-Security-Policy: sandbox allow-forms`, feeds and microformats
for free, the Public Suffix List once there are real users. Bear Blog, Mataroa and Notion
all forbid user code; Obsidian allows it only on a custom domain, never on the shared one.
Nobody does a per-line pin from a private stream. That is our gap to fill.

**Ways in through one small edge.** Cloudflare Email Routing (free), a Turnstile form (free),
a Stripe Payment Link with a webhook (1.5% + €0.25 in Portugal). All three land as records
under the sender's name. One Worker, a few hundred lines.

**Loops run on the owner's side by default.** A Mac at home as a LaunchAgent under a logged-in
user, Optimize Mac Storage off, reached over Tailscale. Hosted loops, when a person has no
Mac, fit Workers for Platforms best: one isolate per loop, CPU caps per call, two cents per
script. Val Town is the fastest prototype and a single vendor. Deno Deploy is winding down
after Cloudflare bought Deno. Wasm sandboxes are too early for people's scripts.

**The reading author as a headless session.** Claude Agent SDK with every built-in tool
stripped and only the door's tools allowed, woken by `whats_new`. A pass costs cents.
OpenAI's dots are the contrast: the data goes to their computer; ours acts through a door
the person serves.

## What is not possible

- **Screen Time cannot be read by an app.** The report extension cannot write anywhere. The
  one outward signal is a threshold event, with a known iOS 26 bug. The "no scrolling"
  streak cannot resolve itself from the phone. It can resolve from the owner's word, or from
  a limit set in Screen Time that the owner reports. The landing page overstates this.
- **iCloud Drive has no "keep downloaded" API** and can hold a file undownloaded for minutes
  or forever with no signal. The fold must tolerate late files (it does, by count per file).
  The Mac that runs loops must have Optimize Storage off and the folder pinned.
- **CloudKit's public database** is readable from the web but its quotas are unpublished.
  Not a place for pages.

## The fork, as three options

**A. Mac plus static hosting.** The Mac folds, runs loops, publishes pages by uploading
files. Cloudflare serves them under name.dotto.works and runs the one edge Worker for forms,
mail and payments, which queue records the Mac pulls. Cost: the domain. Risk: the Mac is the
uptime; the door is reachable only over Tailscale; a person without a Mac cannot run loops.

**B. A server of ours.** A small machine (Fly or Railway) holds a copy of the notebook, runs
loops around the clock, serves the door and the pages. Cost: €5 to €25 a month. Risk: the
words leave the device unless encrypted, which means building sync and keys before anything
else; more to run; but reliable and shareable from day one.

**C. By role.** Cloudflare for everything public and stateless: pages, feeds, forms, mail,
payments, custom domains. The Mac for everything that touches the notebook: the fold, loops,
the reading author. Records published as one SQLite file beside the pages so a page can read
them without a server. Workers for Platforms later for people without a Mac. A relay only
when grants between people arrive.

The author's recommendation is C. It is A with the pieces named so that each can be moved
later without changing the pages, and it is the only one where the words stay on the
person's devices without new sync code.

## Steps, in order, each shippable on its own

0. **Domain.** Buy dotto.works. Cloudflare zone, DNS only. Nothing points anywhere yet.
1. **Pin.** A mark on a line or photo that means "for the outside". Owner's gesture, after
   the fact. Taken back like any mark.
2. **Pages in the folder.** The projector writes `pages/` into the notebook from pinned
   lines, and an author can write a page through the door. Open the folder in a browser
   and it works with no host at all.
3. **Publish.** The Mac uploads `pages/` to Cloudflare under name.dotto.works, uploading only
   what changed. dotto.works itself is served the same way from `site/`. The first loop,
   said in words: publish my pages. This is milestone v0.
4. **Records.** One open fact on a line, folded into one SQLite file per notebook,
   published beside the pages. First use: the yield. The page reads it with sqlite-wasm over
   range requests, or is rendered from it at publish time.
5. **Ways in.** One edge Worker: a Turnstile form, an email address, a Stripe Payment Link
   webhook. Each becomes a record under the sender's name, pulled by the Mac. First use: the
   oil sale.
6. **Loops as sentences.** Kept in the notebook, run on the Mac, a receipt per run. The six
   sentences on the page as the test set.
7. **The reading author, always on.** A headless session with door tools only, woken by
   `whats_new`, on the Mac.
8. **Feeds and the suffix list.** RSS and JSON Feed, microformats, Bridgy Fed when someone
   asks to follow, PSL when there are real users, custom domains through Cloudflare for SaaS.
9. **The apps,** redrawn under the name.
